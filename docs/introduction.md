# Introduction — GSAM 2026

The proliferation of Large Language Model (LLM)-powered applications across consumer-facing domains has accelerated markedly since 2023, with personal finance emerging as one of the earliest and most consequential deployment contexts. Budgeting assistants, expense categorisers, fraud alert systems, and automated financial advisors now routinely integrate third-party LLM APIs — including OpenAI, Anthropic, and open-weight alternatives — to provide natural language interfaces over sensitive user financial data [5]. The appeal is clear: LLMs can interpret ambiguous user queries, summarise complex transaction histories, and surface actionable insights without requiring structured query interfaces. However, this integration introduces a class of security and privacy risks that the financial technology (fintech) sector has not previously encountered, and for which existing defensive tooling is inadequate.
Two risk classes are of particular concern. The first is PII leakage: when a user queries a finance chatbot about their account, transaction history, or payment counterparties, the raw text of that query — including account numbers, sort codes, National Insurance numbers, and named individuals — is transmitted verbatim to a third-party LLM API. These providers may log, retain, or use such data for model training, and any data breach at the provider level directly exposes user financial identifiers. This constitutes a data minimisation violation under GDPR Article 5(1)(c) [1] and presents particular regulatory risk under the UK Financial Conduct Authority's operational resilience framework. The second risk class is prompt injection: malicious payloads embedded in transaction descriptions, merchant name fields, or imported bank statement rows can hijack LLM behaviour, causing the model to reveal system context, propose unauthorised financial operations, or exfiltrate data through crafted response URLs [6]. Unlike traditional injection attacks against databases, prompt injection exploits the LLM's instruction-following behaviour rather than a parsing vulnerability, making it resistant to conventional input sanitisation approaches [3].
Existing defensive tools address these risks in isolation. Microsoft Presidio [10] provides robust PII detection and pseudonymisation but offers no injection defence. LLM Guard [9] and PromptGuard 86M provide injection classification but introduce substantial latency (300ms and 291ms respectively) and are calibrated against general-purpose injection corpora that do not reflect the specific attack surface of financial applications. As this work demonstrates, PromptGuard 86M produces an 80.4% false positive rate on legitimate financial queries — rendering it unsuitable for fintech deployment where query refusal directly degrades user experience and erodes trust. No existing open-source tool provides an integrated, fintech-specific solution combining PII protection, injection defence, and output validation in a single deployable pipeline.
This paper addresses that gap. We present Fintech LLM Guardrails, an eight-layer middleware pipeline interposed between a personal finance application and its LLM API. The system makes the following contributions:

A fintech-specific prompt injection taxonomy comprising eight attack vectors — including transaction description injection, bank statement import injection, obfuscated encoding attacks, and fabricated context manipulation — derived from the threat surface of real personal finance applications and underrepresented in existing benchmarks [3][6].
Five novel middleware components extending a four-layer foundation: a context provenance tracker that labels text by origin and detects indirect injection in imported financial data [6]; a continuous risk-scoring policy engine computing a composite threat score across five weighted dimensions; a declarative action allowlist enforcing separation between LLM proposal and system execution; a canary token system detecting prompt extraction and context leakage [Bowen et al., 2009]; and an adaptive red-team evaluator generating mutation variants of known attacks to measure robustness beyond static benchmarks.
An empirical evaluation demonstrating 100% detection on a 107-case fintech-specific corpus at 0% false positive rate and 5.8ms mean latency — a 51× latency improvement over LLM Guard — with semantic preservation measured via ROUGE-1 (0.986) and BERTScore F1 (0.772). Extended adaptive evaluation across 377 cases including 270 mutation variants yields a 57.1% overall detection rate under evasion, with 100% detection of direct instruction override attacks.
An open-source implementation as a proof-of-concept extension to a working Angular and Flask personal finance application, providing a replicable engineering pathway toward GDPR-compliant [1] LLM deployment in regulated financial environments.
